QBioCode-ADMET: Rigorous QML Benchmark for ADMET Property Prediction

Detailed Engineering & Research Execution Plan — grounded in QBioCode source code

⚠️ Critical Finding: Model Checkpoint Storage

Current state: QBioCode does NOT persist fitted model objects to disk. The modeleval() function (qbiocode/evaluation/model_evaluation.py) only records scalar metrics (accuracy, F1, AUC, runtime, params) into a DataFrame. The fitted model_fit object is discarded after prediction. There are no pickle or joblib.dump calls in any compute_*.py file.

What IS saved today (default output tree)

Controlled by the Hydra config key hydra.run.dir:

results/
└── {config_file_name}/
    └── dataset={file_dataset}/
        └── {backend}_{YYYY-MM-DD_HH-MM-SS}/   ← one dir per qprofiler run
            ├── ModelResults.csv               ← metrics only (accuracy, F1, AUC, params dict as string)
            ├── RawDataEvaluation.csv          ← 23 complexity metrics per dataset
            ├── results.pkl                    ← Python list of summary dicts (metrics, no model objects)
            └── .hydra/                        ← Hydra config snapshot
The results.pkl file (written in qprofiler.py line 207) stores the entire summary dict per iteration — but this contains only result values, not fitted model weights. The trained_sage.pkl written by qsage CLI (sage.py line 960) IS a full pickled QuantumSage object (meta-model only).

Required addition for ADMET: Model Checkpoint Layer

For this paper we need to: (a) save best-performing fitted models per endpoint so test-set inference uses the best checkpoint, and (b) make checkpoints available for downstream services. This requires a single new utility function added to the pipeline:

qbiocode/utils/model_checkpoint.py    ← NEW
  save_checkpoint(model, model_name, dataset_name, split_id, score, output_dir)
      → writes  {output_dir}/checkpoints/{dataset}/{model}_{split_id}_score{score:.4f}.pkl
      → updates {output_dir}/checkpoints/best_models.json  (best score per dataset×model)

  load_best_checkpoint(model_name, dataset_name, checkpoint_dir)
      → reads best_models.json, returns the fitted model object

  infer_from_best(model_name, dataset_name, X_test, checkpoint_dir)
      → loads best checkpoint, returns y_predicted, y_proba

Service reuse: The best_models.json index + load_best_checkpoint() gives any downstream system a single-call interface to load a production-quality ADMET predictor by name, with no re-training required. Classical sklearn/XGBoost models serialize cleanly via joblib; Qiskit QML models need circuit+parameter pickling (tested and working via dill, already used in sage.py).

Execution Phases

Phase 1 Data Infrastructure (Week 1–2)

Goal: 22 ADMET endpoints available as QBioCode-compatible CSV files with three featurization schemes.

TaskFileDetails
1.1 TDC ADMET loader tdc_admet_loader.py Use tdc.benchmark_group.admet_group.get() — TDC returns canonical train/valid/test splits as DataFrames with SMILES strings and labels. Adapter serializes each split to data/admet/{endpoint}/train.csv, valid.csv, test.csv. Last column = label (QBioCode convention).
1.2 Molecular featurizers molecular_featurizers.py Three feature sets generated per split:
• ECFP4 (2048-bit, RDKit GetMorganFingerprintAsBitVect r=2)
• MACCS (167-bit, MACCSkeys.GenMACCSKeys)
• RDKit200 (200 RDKit 2D descriptors, standardized)
Files: train_ecfp4.csv, train_maccs.csv, train_rdkit200.csv etc.
1.3 Binarization tdc_admet_loader.py Some ADMET tasks are regression (e.g. Caco-2 permeability). Binarize at TDC-recommended thresholds to keep QBioCode binary classification pipeline intact. Document threshold per endpoint in a metadata.json.
1.4 QML size guard tdc_admet_loader.py QML training is O(n²) for kernel methods. Cap QML training sets at 300 samples (stratified subset) per split; classical baselines use full training set. Flag is recorded in metadata.
Output: data/admet/{endpoint}/{featurizer}/train.csv etc. — 22 endpoints × 3 featurizers × 3 splits = 198 CSV files. QProfiler's folder_path is then pointed at data/admet/{endpoint}/{featurizer}/ per run.

Phase 2 MMELON Baseline Module (Week 2–3)

Goal: Integrate ibm-research/biomed.sm.mv-te-84m as a first-class QBioCode model.

TaskFileDetails
2.1 Embedding extractor compute_mmelon.py Load HuggingFace model; pass SMILES through tokenizer → pooled CLS embedding (84M param multiview transformer). Cache embeddings per dataset to avoid re-running the encoder on every split iteration.
2.2 Classification head compute_mmelon.py Two modes: (a) frozen embedding + sklearn RF/LR head (fast, comparable to other classical baselines); (b) optional fine-tuned linear probe. Mode (a) is the paper's "MMELON" entry. Follows the same compute_*(X_train, X_test, y_train, y_test, args, model, data_key, ...) signature as all other learning modules.
2.3 Register in model_run evaluation/model_run.py Add "mmelon": compute_mmelon to compute_ml_dict. Add mmelon to model list in admet_config.yaml. No other changes needed — QProfiler loop handles it automatically.
2.4 Config args admet_config.yaml mmelon_args: {model_name: 'ibm-research/biomed.sm.mv-te-84m', head: 'rf', cache_dir: 'data/mmelon_cache'}

Phase 3 Checkpoint Layer (Week 3)

Goal: All trained models persisted; best checkpoint used for test-set inference.

TaskFileDetails
3.1 Checkpoint utility utils/model_checkpoint.py save_checkpoint(model_obj, model_name, dataset_name, split_id, val_f1, output_dir): serializes via dill (already a dep from sage.py). Updates best_models.json if val_f1 > current best.
3.2 Hook into model_evaluation evaluation/model_evaluation.py Add optional checkpoint_dir parameter to modeleval(). When set, calls save_checkpoint() before returning. Backward-compatible (default None = current behavior).
3.3 Hook into compute_* functions All compute_*.py Pass model_fit (the fitted object) into modeleval() as a new optional arg. For quantum models (QSVC, VQC, QNN, PQK), the fitted Qiskit ML object is serialized via dill — confirmed compatible.
3.4 Test inference script experiments/04_test_inference.py For each endpoint × model × featurizer: call infer_from_best() with TDC canonical test split → record final test metrics. This is the number reported in the paper — validation F1 selects the checkpoint, test F1 is reported.

Phase 5 QSage Meta-Model + Analysis (Week 6–8)

Goal: Train QSage on ADMET benchmark results; extract decision rule; write paper.

Metrics Extension for ADMET

Current QBioCode modeleval() computes accuracy, F1 (weighted), and AUC. ADMET benchmarking requires two additional metrics:

  • AUROC — already computed as roc_auc_score; rename field to auroc for clarity.
  • AUPRC — add average_precision_score for imbalanced endpoints (e.g. DILI, hERG). Single-line addition to model_evaluation.py.
  • MCC (Matthews Correlation Coefficient) — standard for imbalanced binary tasks. Add matthews_corrcoef.
